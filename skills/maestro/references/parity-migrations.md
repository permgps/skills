# Reference Discovery for Preservation Work

Open this file only when the request asks to reproduce, migrate, port, clone,
replace, or preserve an existing product or artifact. Read the user's request
and later additions before looking for the literal word “reference.” A named
`legacy/` tree, deployed application, URL, screenshot, archive, or document can
be authoritative even when called “the old app” or “what exists today.”

## Register the authority

For every declared source, assign a stable `REF-*` ID in
`verification.references`. Record the identifying user statement, role,
location, access method, availability/limitation, revision or capture identity,
conditions (viewport, locale, authentication variant, and data), and any
user-approved deviation IDs. Preserve an unavailable declaration. Never
substitute a generated mockup, infer approval from silence, or treat a
contextual example as authoritative behavior without user instruction.

`reference.md` is a readable projection of the neutral register: identity,
role, location, access, conditions, availability, and provenance. Keep
implementation plans, verdicts, and suspected defects out of the neutral
version sent to an independent reader.

## Bound discovery

Inventory user-visible surfaces and distinct states before finalizing the
specification. Read relevant templates, components, styles, assets,
controllers, routes, and configuration. Exercise a live reference when an
authorized browser capability is available. Record observed, source-derived,
or unresolved for each obligation. Source text cannot establish an executed
observation; a signature or event-listener search cannot establish behavior.

Scope the search to known application roots and linked assets. Exclude caches,
uploads, generated output, vendor trees, and credential-bearing paths. Stop a
branch when it ceases to bear on the requested surface, and record what remains
uninspected. Use equivalence groups for genuinely shared components; keep
distinct routes, breakpoints, locale, authentication, and data variants when
they can change visible behavior.

For an interaction, inventory the initial state, trigger, sustained state,
content, exit state, and required resource behavior. The catalog menu example
needs pointer entry, panel entry, columns, links, promotion, images, and
pointer exit. Do not reduce that to “the menu component exists.” For non-UI
work, inventory the applicable output and checks without creating UI records.

## Independent discovery and reconciliation

Give a fresh reader the user request/additions and neutral raw reference
locations. The reader first inspects authority independently and reports
observations with provenance. Do not hand it the generated inventory, spec,
task rationale, or expected verdict before this pass. Reconcile the independent
observations against the inventory afterward. Add grounded missing obligations,
preserve the finding ID, and leave unavailable surfaces explicit. G2 cannot
pass while mandatory coverage is unresolved or an authoritative reference is
silently omitted.
